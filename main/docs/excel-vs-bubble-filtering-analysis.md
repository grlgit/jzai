# Excel vs 气泡过滤准确性分析

**日期**: 2026-07-14
**状态**: 分析完成

## 问题描述

用户反馈：气泡标注数量（125个）远超Excel中的检验项目数量（~20-40个），但Excel的检验项目识别是准确的。

## 根本原因

### 数据流对比

#### 气泡生成流程（Handler-only，无LLM过滤）

```
PDF文本 → isDimensionText()规则过滤 → 125项 → drawing_generate_bubbles → 125个气泡
```

**特点**：
- 完全依赖 `isDimensionText()` 的规则判断
- 无智能过滤步骤
- 假阳性率高（图号、序号等被误判为尺寸）

#### Excel生成流程（Agent + LLM智能过滤）

```
PDF文本 → isDimensionText()规则过滤 → 125项 → Skill返回给Agent
                                                        ↓
                                               **Agent LLM分析判断**
                                                        ↓
                                            识别真正的检验项目（~20-40项）
                                                        ↓
                                              export_excel工具调用
                                                        ↓
                                            Excel包含~20-40行检验项目
```

**特点**：
- Skill返回原始125项给Agent
- **Agent LLM进行智能分析**："先让我分析图纸的关键信息，整理出检验项目"
- LLM理解上下文，过滤掉：
  - 图号中的数字（801、102等）
  - 零件编号
  - 序号和计数
  - 文档结构信息（页码、数量等）
- 只保留真正的尺寸标注

### 关键差异

| 维度 | 气泡生成 | Excel生成 |
|------|---------|-----------|
| 过滤方式 | 纯规则 (`isDimensionText()`) | 规则 + LLM智能判断 |
| 过滤时机 | Handler内部 | Agent收到数据后 |
| 上下文理解 | 无 | 有（LLM理解图纸结构） |
| 假阳性率 | 高（~125个） | 低（~20-40个） |
| 准确性 | 低 | 高 |

### 日志证据

从后端日志可以看到Agent的分析过程：

```
[Nest] 20  - 07/14/2026, 3:00:04 PM  DEBUG  [DynamicAgentService] [main]
onPayload: msg[6] role=assistant len=441 tool_calls=[export_excel]
snippet=好的，系统已识别了125个尺寸标注并生成了标注图纸。现在我来分析这些尺寸并生成检验报告Excel。

先让我分析图纸的关键信息，整理出检验项目。
```

关键短语："**现在我来分析这些尺寸并生成检验报告Excel**"、"**先让我分析图纸的关键信息，整理出检验项目**"

这说明Agent在调用 `export_excel` 之前，先对125项进行了分析和整理。

## 结论

Excel准确性高的原因：
1. **LLM智能过滤**：Agent使用LLM能力理解图纸结构，识别真正的检验项目
2. **上下文理解**：LLM能区分图号、零件号和尺寸标注
3. **两步过滤**：规则过滤（粗筛） + LLM过滤（精筛）

气泡不准确的原因：
1. **规则过滤局限**：`isDimensionText()` 只能基于模式匹配，无法理解上下文
2. **无智能分析**：Handler直接使用规则输出，无LLM参与
3. **假阳性高**：机械图纸中大量非尺寸数字被误判

## 改进方向

要解决气泡过多问题，有以下几种方案：

### 方案1：在Handler中添加LLM过滤（推荐）
在 `drawing-dimension-inspector` skill的handler中，调用Agent服务对125项进行智能过滤，再生成气泡。

**优点**：
- 与Excel生成使用相同的智能过滤逻辑
- 气泡数量与Excel检验项目数量一致
- 一次调用解决两个问题

**缺点**：
- 增加handler执行时间（需要LLM调用）
- 需要Agent服务在skill上下文中可用

### 方案2：改进规则过滤（有限改善）
优化 `isDimensionText()` 的规则，更精确地排除非尺寸文本。

**优点**：
- 无需LLM调用，快速
- 简单直接

**缺点**：
- 规则永远无法完美（边缘情况多）
- 无法处理复杂图纸结构
- 需要不断调整规则

### 方案3：分离气泡和Excel的过滤逻辑
保持气泡使用规则过滤，Excel使用LLM过滤，接受两者的差异。

**优点**：
- 实现简单
- 气泡生成快速

**缺点**：
- 用户体验不一致（气泡多、Excel少）
- 气泡标注意义降低

## 建议

采用**方案1**，在skill handler中添加智能过滤步骤：
1. 解析PDF得到N项（粗筛）
2. 调用Agent服务分析N项，得到M项真正的检验项目（精筛）
3. 只对M项生成气泡和返回给Agent

这样气泡数量将与Excel检验项目数量一致，用户体验最佳。
